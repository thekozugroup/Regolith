# Regolith UI audit — 2026-08-02

## Anti-pattern verdict

Pass with reservations. Regolith has a coherent industrial control identity, restrained frost, strong state visibility, and consistent safety language. It still carries two template-like traits: most information is presented in equal-weight bordered cards, and expert telemetry is exposed before the user asks for it.

## Executive summary

- 3 high-severity findings, 4 medium-severity findings, 2 low-severity findings.
- Highest impact: duplicate Moonraker connection attempts while a socket is connecting, unbounded/redundant camera probes, and no novice/expert disclosure boundary.
- Baseline quality: 86/100. Safety and accessibility are strong; simplicity, connection resilience, and initial-load performance need work.

## High-severity findings

### Duplicate WebSocket connection race

- Location: `src/lib/moonraker.ts`, `src/lib/usePrinter.ts`
- Category: Stability / Performance
- Impact: Multiple components call `connect()`. A socket in `CONNECTING` state is not treated as active, so another call can replace it and create redundant connections, callbacks, and reconnect churn.
- Recommendation: Treat both `CONNECTING` and `OPEN` as active, bind lifecycle handlers to their originating socket, reject pending work on disconnect, and use capped exponential reconnect delay.
- Fix command: `/harden`, `/optimize`

### Camera recovery creates repeated failed requests

- Location: `src/components/CameraStream.tsx`
- Category: Stability / Performance
- Impact: The MJPEG image watchdog and a 1.5-second snapshot probe operate together. An offline camera creates persistent connection failures and never settles into a calm, recoverable state.
- Recommendation: Use one stream health path, capped exponential retry, a clear reconnecting state, and a manual retry after automatic attempts are exhausted.
- Fix command: `/harden`, `/optimize`

### Expert complexity is exposed by default

- Location: `src/components/Sidebar.tsx`, `src/pages/Dashboard.tsx`, `src/pages/Control.tsx`, `src/pages/Settings.tsx`
- Category: Information architecture / Usability
- Impact: A first-time user encounters Console, calibration, pressure advance, host telemetry, bounds, and firmware controls alongside common printing tasks. This raises cognitive load and increases the chance of entering a risky workflow accidentally.
- Recommendation: Default to a persisted Basic experience. Keep print status, temperature, camera, movement safety, and emergency stop visible. Reveal calibration, console, low-level telemetry, profiles, recovery, and host details in Expert mode.
- Fix command: `/distill`, `/frontend-design`

## Medium-severity findings

### Monolithic production JavaScript

- Location: `src/App.tsx`
- Category: Performance
- Impact: The 714.33 kB route bundle includes every page and Recharts before the first screen is usable.
- Recommendation: Lazy-load route modules, preserve an accessible loading state, and verify update-time chunk recovery.
- Fix command: `/optimize`

### Equal-weight card hierarchy

- Location: Dashboard, Tune, Settings
- Category: Visual hierarchy
- Impact: Dense grids of similarly styled cards make common status and uncommon maintenance tasks appear equally important.
- Recommendation: Remove expert-only sections from Basic mode and use spacing/disclosure to create priority before adding more surface styling.
- Fix command: `/distill`, `/polish`

### Technical copy appears before plain-language context

- Location: Dashboard telemetry, Control safety details, Tune actions, Settings host data
- Category: UX writing
- Impact: Acronyms such as PID, PA, Klipper, and Moonraker assume printer expertise.
- Recommendation: Keep technical terms in Expert mode and lead user-facing states with the practical consequence.
- Fix command: `/clarify`, `/distill`

### Settings polls system details while hidden from most users

- Location: `src/pages/Settings.tsx`
- Category: Performance / Stability
- Impact: The page makes four requests initially and continues polling every five seconds even when host details are not needed.
- Recommendation: Load host diagnostics only in Expert mode and retry explicitly after a failure.
- Fix command: `/optimize`, `/harden`

## Low-severity findings

### Camera status starts optimistic

- Location: `src/components/CameraStream.tsx`
- Category: Trust / Polish
- Impact: The badge says Live before a frame loads.
- Recommendation: Start with Connecting and announce recovery changes.

### No global experience explanation

- Location: Settings
- Category: Onboarding
- Impact: Users cannot choose whether the UI should prioritize everyday printing or expose maintenance controls.
- Recommendation: Add a concise Basic/Expert selector with explicit consequences.

## Positive findings

- Printer-affecting actions share live-state guards and duplicate-action locks.
- Touch targets, focus visibility, modal focus management, reduced motion, headings, and responsive overflow already pass exact-current checks.
- Frosted blur is limited to navigation and status chrome.
- Mobile navigation adapts to four reachable targets instead of shrinking the desktop sidebar.
- Deployment is idle-gated, verified, reversible, and backed up before swap.

## Priority

1. Fix connection races and bounded recovery.
2. Add Basic/Expert progressive disclosure without hiding safety state.
3. Split routes and measure bundle changes.
4. Verify offline, recovery, keyboard, mobile, desktop, and live-device behavior.
